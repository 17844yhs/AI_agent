# Agent 工具调用与接口设计

## 🎯 为什么需要工具调用？

> 💡 **比喻**：工具是Agent与现实世界交互的"手和眼"，类似手机安装的各种APP

```
Agent本身 ❌ 不具备执行外部操作能力
   ↓
通过工具调用 ✅ 动态扩展功能
```

---

## 🛠️ 工具类型对比

| 工具类型    | 类比APP    | 功能示例           |
| ----------- | ---------- | ------------------ |
| 🔍 搜索工具 | 百度/谷歌  | 查资料、找答案     |
| 🧮 计算工具 | 计算器     | 数学计算、数据分析 |
| 📄 文件工具 | WPS/Office | 读写文档、处理表格 |
| 💻 代码工具 | GitHub     | 写代码、调试程序   |
| 🏠 生活工具 | 美团/12306 | 订餐、订票、查天气 |

---

## 🔄 工具调用核心流程

```
任务解析 → 工具匹配 → 参数生成 → 执行调用 → 结果处理
```

### 示例：查询天气

```python
# 用户问："北京明天天气如何"
agent.use_tool("weather", {
    "city": "北京", 
    "date": "tomorrow"
})

# 返回结果
{
  "city": "北京",
  "date": "2050-06-01", 
  "weather": "晴",
  "temp": "22℃",
  "suggestion": "适合出游，记得防晒"
}
```

## 📐 工具抽象核心思想

| 原则               | 说明                                        |
| ------------------ | ------------------------------------------- |
| **统一接口** | 所有工具暴露一致的调用方式                  |
| **描述驱动** | 提供清晰的名称、描述、参数说明（供LLM理解） |
| **可组合性** | 多个工具可串联使用，支持复杂任务分解        |

---

## ✅ 接口设计四大原则

### 1️⃣ 统一接口与描述驱动

> 工具描述是给LLM的"说明书"

### 2️⃣ 输入/输出契约

- 明确定义参数类型、格式、必填项
- 返回结构包含成功/失败状态

### 3️⃣ 错误处理机制

```
✅ 工具内部捕获异常，避免中断Agent流程
✅ 返回结构化错误信息：{"error": "Invalid API key"}
✅ 便于Agent决策重试或换策略
```

### 4️⃣ 幂等性与安全性

- ⚠️ 避免重复调用产生副作用（如多次扣款）
- 🔒 敏感操作需权限校验

## 🔑 核心洞察

> **工具设计黄金法则**：
>
> 1. 描述清晰 → LLM才能正确调用
> 2. 错误友好 → Agent才能优雅处理
> 3. 接口统一 → 系统才能灵活扩展
> 4. 安全第一 → 防止滥用和越权
