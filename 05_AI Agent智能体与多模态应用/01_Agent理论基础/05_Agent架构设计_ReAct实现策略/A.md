# Plan-and-Execute 架构

## 🎯 核心概念

**两阶段设计**：规划（Plan）+ 执行（Execute）

```
Planner（规划器）→ 生成任务计划
Executor（执行器）→ 按步骤执行 + 反馈结果
      ↓
  遇错 → 重规划 → 继续执行
```

> 💡 **比喻**：ReAct是"边走边想的探险家"，Plan-and-Execute是"先画地图再行军的指挥官"

---

## 🔑 四大设计原则

| 原则 | 说明 |
|------|------|
| **规划先行** | 行动前生成任务蓝图（步骤/依赖/回滚点） |
| **执行隔离** | Executor只负责"如何做"，不参与决策 |
| **反馈驱动** | 失败时Planner基于反馈触发重规划 |
| **事务保障** | 幂等操作 + 补偿机制确保一致性 |

---

## ⚙️ 关键设计要点

- ✅ **任务原子化**：拆解为不可再分的独立操作
- ✅ **依赖显式建模**：明确前置条件，避免无效执行
- ✅ **幂等性与补偿**：所有动作可重试，不可逆则提供补偿
- ✅ **结构化反馈**：Executor返回标准化状态码
- ✅ **重规划策略**：内置重试/降级/替换/回滚方案

---

## 📝 工作流程示例

**任务**：完成"航班+酒店+租车"预订

### 1️⃣ Planner 生成计划
```
① 获取出行信息
   ↓ (依赖①)
② 预订航班
   ↓ (依赖②)
③ 预订酒店
   ↓ (依赖③)
④ 预订租车
   ↓ (依赖④)
⑤ 汇总通知用户
```

### 2️⃣ 异常处理
```
❌ 步骤③失败（酒店满房）
   ↓
Executor 返回错误码: HOTEL_UNAVAILABLE
   ↓
Planner 重规划：
  • 扩大搜索范围
  • 调整入住日期
  • 提示用户确认
   ↓
✅ 重新执行子计划
```

## 🆚 vs ReAct 对比

| 维度 | ReAct | Plan-and-Execute |
|------|-------|------------------|
| **决策节奏** | 逐步推理+即时行动 | 先全局规划→批量执行 |
| **适用场景** | 信息不全、需探索 | 流程固定、需事务保障 |
| **执行效率** | 低（每步都需LLM推理） | 高（计划一次生成） |
| **容错机制** | 隐式纠错 | 显式建模失败路径 |
| **架构层级** | 算法层策略 | 系统层架构 |

---

## 💡 混合架构建议

**"Plan-and-Execute为主干，ReAct为叶子节点"**

```
Planner → 结构化逻辑生成主流程
   ↓
Executor → 内部使用ReAct动态调用工具
```

> ✅ **优势**：结合两者优点，既有全局规划又有局部灵活性
