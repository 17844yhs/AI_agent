# ReAct 架构：推理 + 行动循环

## 🎯 核心概念

**ReAct = Reasoning（推理）+ Acting（行动）**

> 💡 **比喻**：传统LLM是"只会背书的学者"，ReAct是"带着笔记本解题的研究员"——边思考边行动

---

## 🔄 工作流程

```
Thought（思考）→ Action（行动）→ Observation（观察）→ Thought → ...
```

### 核心机制
1. **交替进行**：生成思考 ↔ 执行动作
2. **外部交互**：调用工具/API获取真实信息
3. **动态调整**：基于观察更新推理路径

---

## ✅ 三大优势

| 优势 | 说明 |
|------|------|
| **可解释性强** | 保留完整思考链，便于调试审计 |
| **成功率更高** | 思考帮助准确选择工具和参数 |
| **灵活纠错** | 根据工具返回调整后续步骤 |

---

## 📝 实战示例

**用户**："服务器响应很慢，帮我查一下原因"

```
🤔 Thought: 需要检查CPU、内存、网络和日志
🛠️ Action: 调用监控API获取CPU使用率
👁️ Observation: CPU使用率正常（30%）

🤔 Thought: 排除CPU问题，检查内存
🛠️ Action: 调用监控API获取内存使用率
👁️ Observation: 内存使用率95%，接近满载

✅ Answer: 发现内存使用率过高，建议检查是否有内存泄漏
```

---

## 🔑 核心价值

> **解决幻觉问题**：通过工具调用获取真实信息，减少LLM凭空臆造  
> **适用场景**：故障排查、数据分析、需要实时信息的任务
