# 编写简单的 Skill

## Skill 目录结构

```
~/.claude/
├── skills/
│   ├── iwen-creative/
│   │   ├── SKILL.md          # 主要说明（必填）
│   │   ├── references/       # 附加文档
│   │   ├── scripts/          # 可从 skill 调用的帮助程序脚本
│   │   └── assets/           # 补充文件
│   └── 技能2/
│       └── SKILL.md
```

> 这些目录结构并不是每个都是必需品，**只有 `SKILL.md` 是不可或缺的**！并且目录结构是可以自己创建的！

## iwen 餐厅创意文案 — SKILL.md 示例

```yaml
---
name: iwen-creative
description: 为iwen餐厅生成符合品牌调性的物料设计创意，当用户说要做某种物料(海报、易拉宝、工服、包装盒等)，你需要输出这个物料的设计创意。
---
```

```markdown
# iwen-creative — 为iwen餐厅生成符合品牌视觉规范的各类营销物料，输出创意方案

## 品牌核心元素
- 品牌名: iwen餐厅
- 风格: 年轻、潮流、有网感
- IP形象: 布偶猫
- 主色: 薄荷绿 #5DDEB5
- Slogan: A FRESH, MODERN BITE / 健康轻食主义
- 风格: 3D 卡通、清新时尚、年轻活力

## 你的任务
当用户说要做某种物料(海报、易拉宝、工服、包装盒等)，你需要输出这个物料的设计创意描述。

## 输出格式
请按以下格式输出:

### 创意主题
(一句话概括这个设计的核心概念)

### 视觉风格
(整体氛围、配色方向、质感)

### 画面构成
(主体元素、背景、装饰元素的布局描述)

### 细节建议
(一些能让设计更出彩的小细节)
```

## Skill 与提示词的区别

| 维度 | 提示词（Prompt） | Skill |
|------|-----------------|-------|
| **复杂度** | 适合简单、单步任务（翻译、摘要、问答） | 能处理复杂的、多步骤的工作流 |
| **可复用性** | 每次使用可能都需要微调 | 封装好、可重复调用，用户只需触发 |
| **依赖与执行** | 只依赖模型自身知识 | 可依赖外部工具/数据源，甚至执行代码确保准确性 |
| **按需加载** | 每次完整传输 | 按需加载，多个 Skill 共存不增加 Token 消耗 |

### 一个很好理解的比喻

- **提示词** → 犹如你问一位专家："告诉我关于黑洞的知识。" 专家直接凭记忆回答。
- **Skill** → 犹如你要求一个工作小组："帮我做一个关于黑洞的10页PPT。" 这个小组会：1）查资料；2）写大纲；3）设计页面；4）配图表；5）最终生成PPT。**你只需要下命令，不需要指挥每一步。**
