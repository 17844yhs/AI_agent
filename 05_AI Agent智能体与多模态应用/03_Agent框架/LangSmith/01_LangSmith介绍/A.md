# LangSmith 介绍

## 学习目标

- 理解为什么需要 LangSmith
- 了解 LangSmith 解决的核心问题
- 掌握 LangSmith 的主要功能和价值

---

## 一、为什么需要 LangSmith？

### 问题场景分析

#### 场景1：LCEL 链式调用是黑盒

```python
chain = prompt | llm | parser
result = chain.invoke({"input": "你好"})
```

**疑问**：

- ❓ prompt 发送给 LLM 的完整内容是什么？
- ❓ LLM 返回了什么原始内容？
- ❓ parser 解析是否正确？
- ❓ 哪一步耗时最长？

#### 场景2：LangGraph 执行流程不可见

```python
result = app.invoke({"messages": [HumanMessage("帮我订机票")]})
```

**疑问**：

- ❓ Agent 做了几次决策？
- ❓ 调用了哪些工具？参数是什么？
- ❓ 条件路由走了哪条路径？
- ❓ 为什么输出结果不对？哪一步出了问题？

#### 场景3：Token 消耗是个谜

**疑问**：

- ❓ 今天跑了 50 次调用，花了多少 Token？
- ❓ 哪个 prompt 最耗 Token？
- ❓ 如何优化 Token 使用？

#### 场景4：有了 LangSmith 之后

```python
chain.invoke({"input": "你好"})
```

**结果**：

- ✅ 打开 LangSmith 网页面板
- ✅ 看到完整的调用链：`prompt → llm → parser`
- ✅ 每一步的输入输出、耗时、Token 一目了然
- ✅ 错误时直接定位到出错的步骤

---

## 二、核心问题

**LangChain/LangGraph 的链式调用和 Agent 执行是复杂的多步过程，没有调试工具就像在黑盒中摸索。**

LangSmith 提供了完整的**可观测性**，让每一步调用都清晰可见。

---

## 三、LangSmith 的作用

### 对比：没有 vs 有 LangSmith

| 维度               | 没有 LangSmith                       | 有 LangSmith                         |
| ------------------ | ------------------------------------ | ------------------------------------ |
| **调试方式** | 链式调用是黑盒，不知道内部发生了什么 | 每次调用自动记录完整链路（Trace）    |
| **问题排查** | 除了 bug 只能靠 print 调试           | 输入输出、耗时、Token 一目了然       |
| **执行流程** | 不可见，无法追踪                     | 可视化展示执行流程和分支             |
| **效果对比** | 无法对比不同 prompt 的效果           | 支持评估（Eval）对比不同 prompt 效果 |
| **成本管理** | 不知道 Token 消耗和成本              | 详细的 Token 统计和成本分析          |

### 核心功能总结

1. **Trace 追踪**：记录每次调用的完整链路
2. **可视化面板**：直观展示执行流程和分支
3. **性能分析**：耗时、Token 使用一目了然
4. **评估对比**：支持不同 prompt/模型效果对比
5. **错误定位**：快速定位出错步骤

---

## 四、关键要点总结

| 要点               | 说明                                     |
| ------------------ | ---------------------------------------- |
| **核心价值** | 提供 LangChain/LangGraph 的可观测性      |
| **解决痛点** | 链式调用黑盒、流程不可见、Token 消耗不明 |
| **主要功能** | Trace 追踪、可视化、性能分析、评估对比   |
| **使用方式** | 自动记录，打开网页即可查看               |
