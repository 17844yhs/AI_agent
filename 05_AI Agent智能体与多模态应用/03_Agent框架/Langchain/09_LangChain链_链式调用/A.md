# 🎯 学习目标

建立对"链"(Chain)的本质认知,不涉及具体代码实现

---

## 📋 常见模式

在构建 AI 应用时,我们很少只做"一次提问、一次回答"这样简单的事情。更常见的是:

1. 先理解用户意图
2. 再从数据库或文档中检索相关信息
3. 接着将信息整理成结构化提示
4. 然后调用大模型生成答案
5. 最后对结果进行验证、格式化或后续处理

---

### ❌ 直接调用模型(无链时代)

```python
response = llm.invoke("请总结这篇文档:" + document_text)
```

**问题:**

- 提示工程简单
- 无上下文管理
- 难以扩展

---

### ⚠️ 手动编排(前链时代)

```python
# 手动连接多个步骤
def manual_chain(question):
    # 1. 检索相关文档
    docs = retriever.invoke(question)
  
    # 2. 构建复杂提示
    prompt = f"""基于以下上下文回答问题:
    上下文:{docs}
    问题:{question}
    要求:如果上下文不包含答案,请明确说"我不知道"。"""
  
    # 3. 调用模型
    response = llm.invoke(prompt)
  
    # 4. 后处理
    if "我不知道" in response:
        return "抱歉,我无法回答这个问题。"
    return response
```

**问题:**

- 代码重复
- 难以测试
- 逻辑分散

---

### ✅ 链式编排(现代方法)

```python
# 使用链抽象
chain = (
    retrieve_documents              # 第一步:检索
    | build_context_aware_prompt    # 第二步:构建提示
    | invoke_llm                    # 第三步:调用模型
    | validate_and_format_response  # 第四步:后处理
)

# 单行调用,完整功能
response = chain.invoke({"question": "公司的营收增长率是多少?"})
```

---

## 💡 核心定义

**链(Chain)** 是 LangChain 中用于按特定顺序组织和执行多个组件的机制。它将大语言模型(LLM)与其他工具、数据源、处理逻辑连接起来,形成一个完整的 AI 应用工作流。

---

## 🌟 核心价值

### 价值一:降低认知负荷

开发者无需记住每个组件的细节,只需知道如何将它们连接起来。

### 价值二:促进协作

团队可以分工开发不同组件,通过链定义清晰的接口和交互协议。

### 价值三:加速迭代

通过替换链中的单个组件快速实验不同方案,无需重写整个应用。

### 价值四:提高可靠性

标准化的错误处理、重试机制和验证步骤内置于链框架中。
