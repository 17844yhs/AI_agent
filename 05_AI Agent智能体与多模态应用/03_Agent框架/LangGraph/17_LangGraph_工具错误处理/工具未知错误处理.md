# 🎯 学习目标

- 理解**未知错误**的特点和处理方式
- 掌握 ToolNode 的 `handle_tool_errors` 参数
- 学会手动构建 Graph 实现错误兜底机制

---

## 📖 介绍

**未知错误**是指无法预见的意外异常，如数据库突然断开、第三方 API 返回格式变化等。对于这类错误，ToolNode 可以自动捕获并转为 `ToolMessage` 返回给 Agent，让 Agent 自行决定如何应对。

---

## 💡 适用场景

| 错误类型 | 示例 | 特点 |
|---------|------|------|
| **数据库断开** | `ConnectionError` | 无法预见的连接问题 |
| **API 格式变化** | `KeyError`, `TypeError` | 第三方服务变更 |
| **服务器错误** | HTTP 500 | 服务端内部错误 |
| **资源耗尽** | `MemoryError` | 系统资源不足 |

## 💻 代码示例：手动构建 Graph + handle_tool_errors

```python
import os
from dotenv import load_dotenv
from typing import Annotated, Sequence, TypedDict
from operator import add
from langchain.tools import tool
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage
from langgraph.graph import StateGraph, END
from langgraph.prebuilt import ToolNode, tools_condition

load_dotenv()

llm = ChatOpenAI(
    base_url=os.getenv("OPENAI_API_BASE"),
    api_key=os.getenv("OPENAI_API_KEY")
)

# 模拟一个会抛未知异常的工具
@tool
def query_database(sql: str) -> str:
    """查询数据库，输入SQL语句。"""
    if "error" in sql.lower():
        # 模拟数据库连接突然断了（无法预见的错误）
        raise ConnectionError("数据库连接失败：Connection refused")
    if "user" in sql.lower():
        return "查询结果：张三,25岁,北京 | 李四,30岁,上海"
    return "查询结果：无匹配数据"

# 定义 State
class AgentState(TypedDict):
    messages: Annotated[Sequence, add]

def agent_node(state: AgentState):
    llm_with_tools = llm.bind_tools([query_database])
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

# 构建 Graph
graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", ToolNode(
    [query_database],
    handle_tool_errors=True  # 关键参数！开启错误兜底
))

graph.set_entry_point("agent")
graph.add_conditional_edges("agent", tools_condition, {
    "tools": "tools",
    END: END
})
graph.add_edge("tools", "agent")

app = graph.compile()

# 测试1：正常查询
print("=== 正常查询 ===")
result = app.invoke({"messages": [HumanMessage("查询所有用户信息")]})
print(f"AI：{result['messages'][-1].content}\n")

# 测试2：触发未知异常 → ToolNode 兜底，不会崩溃
print("=== 触发异常（ToolNode兜底） ===")
result = app.invoke({"messages": [HumanMessage("执行SQL: SELECT * FROM error_table")]})
for msg in result["messages"]:
    print(f"  [{msg.type}] {msg.content}")
```

### 📊 运行结果

```
=== 正常查询 ===
AI：查询结果如下：张三,25岁,北京 | 李四,30岁,上海

=== 工具异常（ToolNode兜底） ===
  [human] 执行SQL: SELECT * FROM error_table
  [ai] （调用工具 query_database）
  [tool] Error: 数据库连接失败：Connection refused
  [ai] 抱歉，数据库连接失败了，请稍后重试或联系管理员。
```

## 🔍 handle_tool_errors 工作原理

```python
# ToolNode 内部逻辑（简化版）
class ToolNode:
    def __init__(self, tools, handle_tool_errors=False):
        self.tools = tools
        self.handle_tool_errors = handle_tool_errors
    
    def invoke(self, state):
        for tool_call in tool_calls:
            try:
                # 执行工具
                result = tool.invoke(tool_call["args"])
                return ToolMessage(content=result, tool_call_id=tool_call["id"])
            
            except Exception as e:
                if self.handle_tool_errors:
                    # ✅ 开启兜底：将异常转为 ToolMessage
                    return ToolMessage(
                        content=f"Error: {e}",
                        tool_call_id=tool_call["id"]
                    )
                else:
                    # ❌ 未开启：异常直接抛出，Graph 崩溃
                    raise
```

## ⚠️ 重要注意事项

### 🔴 create_agent 默认不开启 handle_tool_errors

```
# ❌ create_agent 内部的 ToolNode 默认没有开启 handle_tool_errors
app = create_agent(llm, [tool])  # 遇到未知异常会崩溃

# ✅ 解决方案1：手动构建 Graph 并设置 handle_tool_errors=True
graph = StateGraph(AgentState)
graph.add_node("tools", ToolNode([tool], handle_tool_errors=True))

# ✅ 解决方案2：始终在工具内用 try-except 兜底（推荐）
@tool
def my_tool(x: str) -> str:
    try:
        return do_something(x)
    except Exception as e:
        return f"错误：{e}"
```

### 📋 四层防护对比

| 层级 | 策略 | 处理错误 | Agent 感知 | 优势 |
|------|------|---------|-----------|------|
| **第0层** | **Pydantic 验证** | 参数格式、范围、安全限制 | ❌ 直接拒绝，不执行工具 | **前置拦截，节省资源** |
| **第1层** | **tenacity 重试** | 临时错误（网络、限流） | ❌ 无感知，只拿到最终结果 | **自动恢复，透明高效** |
| **第2层** | **try-except** | 已知错误（HTTP错误、格式错） | ✅ 友好提示 | **用户体验好，可控** |
| **第3层** | **handle_tool_errors** | 未知错误（意外异常） | ✅ 错误信息 | **防止崩溃，最后防线** |

---

### 💡 简要说明

#### 第0层：Pydantic 参数验证
- 在工具执行前就拦截非法输入
- 防止注入攻击（XSS、SQL注入等）
- 节省不必要的 API 调用

#### 第1层：tenacity 自动重试
- 自动处理临时性故障
- Agent 完全感知不到中间失败
- 指数退避避免雪崩效应

#### 第2层：try-except 已知错误
- 将技术错误转为用户友好的提示
- 针对不同错误类型给出具体建议
- Agent 可以直接回复用户

#### 第3层：ToolNode 兜底
- 捕获所有未被处理的异常
- 防止 Graph 崩溃
- 让 Agent 有最后的决策机会

## 📋 总结

| 特性 | 说明 |
|------|------|
| **适用错误** | 未知错误（意外异常、不可预见的问题） |
| **处理方式** | ToolNode 自动捕获，转 `ToolMessage` |
| **Agent 感知** | ✅ 拿到错误信息，自行决策 |
| **优势** | 防止 Graph 崩溃，Agent 可灵活应对 |
| **注意** | `create_agent` 默认不开启，需手动构建 Graph |

---

## 🎯 核心要点

- ✅ **未知错误不可预见**：无法提前设计处理逻辑
- ✅ **ToolNode 兜底**：自动捕获异常，转为 ToolMessage
- ✅ **handle_tool_errors**：必须设置为 `True` 才生效
- ✅ **Agent 决策**：拿到错误信息后自行决定如何回复
- ✅ **手动构建 Graph**：create_agent 默认不开启兜底机制
- ✅ **最后防线**：确保系统永不崩溃
