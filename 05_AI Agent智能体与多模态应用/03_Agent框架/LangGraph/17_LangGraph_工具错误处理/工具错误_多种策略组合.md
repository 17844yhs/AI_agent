- 理解**四层防护架构**的设计理念
- 掌握 **Pydantic + tenacity + try-except + handle_tool_errors** 的组合使用
- 学会在生产环境中构建健壮的工具错误处理体系

---

## 📖 介绍

单一的错误处理策略无法应对所有场景。**生产环境**需要组合多种策略，形成完整的防护体系：

```
用户输入 
  ↓
【第0层】Pydantic 参数验证 ← 前置验证，阻止非法输入
  ↓
【第1层】tenacity 重试 ← 临时错误自动恢复
  ↓
【第2层】try-except 捕获 ← 已知错误友好提示
  ↓
【第3层】ToolNode 兜底 ← 未知错误防止崩溃
  ↓
Agent 决策
```

---

## 🏗️ 四层防护架构详解

### 📊 各层职责对比

| 层级            | 策略                         | 处理错误                     | Agent 感知                | 优势                         |
| --------------- | ---------------------------- | ---------------------------- | ------------------------- | ---------------------------- |
| **第0层** | **Pydantic 验证**      | 参数格式、范围、安全限制     | ❌ 直接拒绝，不执行工具   | **前置拦截，节省资源** |
| **第1层** | **tenacity 重试**      | 临时错误（网络、限流）       | ❌ 无感知，只拿到最终结果 | **自动恢复，透明高效** |
| **第2层** | **try-except**         | 已知错误（HTTP错误、格式错） | ✅ 友好提示               | **用户体验好，可控**   |
| **第3层** | **handle_tool_errors** | 未知错误（意外异常）         | ✅ 错误信息               | **防止崩溃，最后防线** |

## 💻 完整代码示例

### 1️⃣ 定义 Pydantic 参数模型（第0层）

```python
from pydantic import BaseModel, Field, field_validator

class SearchInput(BaseModel):
    """搜索API的输入参数"""
    query: str = Field(
        description="搜索关键词",
        min_length=1,
        max_length=100
    )
    limit: int = Field(
        default=10,
        ge=1,
        le=50,
        description="返回结果数量"
    )
  
    @field_validator('query')
    @classmethod
    def validate_query(cls, v):
        """验证查询词不包含危险字符"""
        dangerous_chars = ['<', '>', '&', '"', "'"]
        if any(char in v for char in dangerous_chars):
            raise ValueError(f"查询词包含非法字符: {dangerous_chars}")
        return v.strip()
```

**作用**：

- ✅ 阻止无效参数进入工具
- ✅ 防止注入攻击（XSS、SQL注入等）
- ✅ 节省不必要的 API 调用

### 2️⃣ 实现工具函数（第1-3层）

```python
import os
import requests
from dotenv import load_dotenv
from langchain_core.tools import tool
from tenacity import (
    retry,
    stop_after_attempt,
    wait_exponential,
    retry_if_exception_type
)

load_dotenv()

@tool(args_schema=SearchInput)
@retry(
    stop=stop_after_attempt(3),              # 最多重试3次
    wait=wait_exponential(min=1, max=10),    # 指数退避：1s, 2s, 4s...
    retry=retry_if_exception_type((          # 只重试临时性错误
        requests.exceptions.Timeout,
        requests.exceptions.ConnectionError
    ))
)
def search_api(query: str, limit: int = 10) -> str:
    """搜索互联网信息。"""
    try:
        # ===== 第1层：tenacity 处理临时性错误 =====
        # 网络超时、连接失败 → 自动重试
        response = requests.get(
            f"https://api.example.com/search",
            params={"q": query, "limit": limit},
            timeout=5
        )
        response.raise_for_status()
        results = response.json()["results"]
      
        if not results:
            return f"未找到关于'{query}'的结果"
      
        return f"找到{len(results)}条结果：\n" + "\n".join(results[:limit])
  
    except requests.exceptions.HTTPError as e:
        # ===== 第2层：try-except 处理已知错误 =====
        # HTTP错误 → 友好提示
        if e.response.status_code == 400:
            return "错误：搜索参数不正确，请检查查询词"
        elif e.response.status_code == 401:
            return "错误：API密钥无效"
        elif e.response.status_code == 429:
            return "错误：API调用次数超限，请稍后再试"
        else:
            return f"错误：HTTP {e.response.status_code}"
  
    except ValueError as e:
        # 第2层：处理JSON解析错误
        return f"错误：API返回数据格式异常 - {e}"
  
    except KeyError as e:
        # 第2层：处理数据结构错误
        return f"错误：API返回数据缺少字段 - {e}"
  
    # ===== 第3层：其他未知错误 =====
    # → tenacity 也不重试（因为不是临时错误）
    # → ToolNode 兜底（如果开启 handle_tool_errors）
    # → Agent 决策
```

### 3️⃣ 构建 Graph + ToolNode 兜底（第3层）

```python
from typing import Annotated, Sequence, TypedDict
from operator import add
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, END
from langgraph.prebuilt import ToolNode, tools_condition
from langchain_core.messages import HumanMessage

llm = ChatOpenAI(
    base_url=os.getenv("OPENAI_API_BASE"),
    api_key=os.getenv("OPENAI_API_KEY")
)

# 定义 State
class AgentState(TypedDict):
    messages: Annotated[Sequence, add]

def agent_node(state: AgentState):
    llm_with_tools = llm.bind_tools([search_api])
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

# 构建 Graph
graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", ToolNode(
    [search_api],
    handle_tool_errors=True  # 第3层兜底：开启错误处理
))

graph.set_entry_point("agent")
graph.add_conditional_edges("agent", tools_condition, {
    "tools": "tools",
    END: END
})
graph.add_edge("tools", "agent")

app = graph.compile()
```

## 💡 设计原则

### ✅ 各司其职

| 层级            | 原则               | 说明                       |
| --------------- | ------------------ | -------------------------- |
| **第0层** | **前置拦截** | 越早发现问题，越节省资源   |
| **第1层** | **透明恢复** | Agent 不应该知道临时故障   |
| **第2层** | **友好提示** | 技术错误转为用户能懂的语言 |
| **第3层** | **最后防线** | 确保系统永不崩溃           |

---

### ⚠️ 注意事项

#### 1️⃣ tenacity 只重试临时错误

```python
# ✅ 正确：只重试临时性错误
@retry(retry=retry_if_exception_type((TimeoutError, ConnectionError)))

# ❌ 错误：重试所有异常（包括参数错误）
@retry()  # 参数错误重试多少次都没用！
```

#### 2️⃣ try-except 捕获具体异常

```python
# ✅ 正确：捕获具体异常类型
except requests.exceptions.HTTPError as e:
    if e.response.status_code == 400:
        return "参数错误"

# ❌ 错误：捕获所有异常（会掩盖未知错误）
except Exception:
    return "出错了"
```

#### 3️⃣ Pydantic 验证要全面

```python
# ✅ 正确：多维度验证
class SearchInput(BaseModel):
    query: str = Field(min_length=1, max_length=100)
  
    @field_validator('query')
    def validate_query(cls, v):
        if contains_dangerous_chars(v):
            raise ValueError("包含非法字符")
        return v.strip()

# ❌ 错误：只做基本类型检查
query: str  # 无法阻止 XSS、SQL注入等
```

#### 4️⃣ handle_tool_errors 必须开启

```python
# ✅ 正确：手动构建 Graph 并开启兜底
ToolNode([tool], handle_tool_errors=True)

# ❌ 错误：create_agent 默认不开启
create_agent(llm, [tool])  # 遇到未知异常会崩溃
```

## 📋 总结

### 四层防护的价值

| 特性               | 说明                           |
| ------------------ | ------------------------------ |
| **健壮性**   | 四层防护，层层把关，系统更稳定 |
| **用户体验** | 友好的错误提示，清晰的反馈     |
| **资源效率** | 前置拦截，避免无效调用         |
| **可维护性** | 每层职责清晰，易于调试和优化   |
| **安全性**   | Pydantic 验证阻止注入攻击      |

---

## 🎯 核心要点

- ✅ **四层防护**：Pydantic + tenacity + try-except + handle_tool_errors
- ✅ **各司其职**：每层处理特定类型的错误，互不重叠
- ✅ **前置拦截**：Pydantic 在工具执行前验证参数
- ✅ **透明恢复**：tenacity 自动重试，Agent 无感知
- ✅ **友好提示**：try-except 将技术错误转为用户语言
- ✅ **最后防线**：ToolNode 兜底，确保系统永不崩溃
- ✅ **生产必备**：单一策略不够，必须组合使用
