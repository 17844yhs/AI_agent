# 🎯 学习目标

- 理解工具调用失败的**三种错误类型**
- 掌握**三种错误处理策略**的适用场景
- 了解生产环境中三种策略的**组合用法**

---

## 📖 介绍

Agent 调用工具时，工具可能因为各种原因失败：参数错误、网络超时、API限流等。如果不做错误处理，Agent 会直接崩溃。

LangGraph 的 **ToolNode** 提供了内置的错误处理机制。

---

## 📞 生活化比喻：打电话

| 错误类型 | 场景 | 处理方式 |
|---------|------|---------|
| **已知错误** | 对方号码格式错误 | 直接提示"号码不正确" ✅ |
| **临时错误** | 对方暂时没信号 | 自动每隔几秒重拨，最多3次 🔄 |
| **未知错误** | 对方直接挂断 | 让 Agent 决定怎么办 🤔 |

---

## 🔍 三种错误类型

### 1️⃣ 已知错误（Known Errors）

**特点**：可以预见的错误，如参数不合法、格式错误

**示例**：
- 除数为零：`100/0`
- SQL 语法错误
- 参数格式不正确

**处理策略**：工具内 `try-except` → 返回友好提示

---

### 2️⃣ 临时错误（Transient Errors）

**特点**：暂时性问题，重试大概率成功

**示例**：
- 网络超时
- API 限流
- 数据库连接池满

**处理策略**：`tenacity` 自动重试 → 指数退避

---

### 3️⃣ 未知错误（Unknown Errors）

**特点**：无法预见的意外异常

**示例**：
- 数据库突然断开连接
- 第三方 API 返回格式变化
- 服务器内部错误

**处理策略**：ToolNode 兜底 → Agent 自行决策

---

## 🛠️ 三种错误处理策略

| 策略 | 适用错误类型 | 工作方式 | Agent 感知 |
|------|------------|---------|-----------|
| **try-except** | 已知错误 | 工具内部捕获，返回友好文本 | ✅ 拿到友好文本，直接回复 |
| **tenacity 重试** | 临时错误 | 自动重试 N 次，指数退避 | ❌ 无感知，只拿到最终结果 |
| **handle_tool_errors** | 未知错误 | ToolNode 自动捕获，转 ToolMessage | ✅ 拿到错误信息，自行决策 |

## 💡 问题场景演示

### ❌ 没有任何错误处理的工具

```python
@tool
def calculate(expression: str) -> str:
    """计算数学表达式。"""
    result = eval(expression)  # 遇到 "100/0" 直接崩溃
    return f"计算结果：{result}"

@tool
def query_database(sql: str) -> str:
    """查询数据库。"""
    raise ConnectionError("数据库连接失败")  # 直接抛异常

@tool
def search_web(query: str) -> str:
    """搜索互联网信息。"""
    if random.random() < 0.7:
        raise TimeoutError("请求超时")  # 模拟不稳定网络
    return f"搜索结果：关于'{query}'的内容..."
```

### 📊 运行结果分析

```
=== 已知错误：除零 ===
  [tool] Error: division by zero
  [ai] 抱歉，计算时出错了：除数为零...
  
问题：英文错误信息，用户体验差 ❌

=== 未知错误：数据库断了 ===
  [tool] Error: 数据库连接失败
  [ai] 抱歉，数据库连接失败了，请稍后重试...
  
问题：错误信息可能包含敏感内容（IP、密码）❌

=== 临时错误：网络超时 ===
  [tool] Error: 请求超时
  [ai] 抱歉，搜索请求超时了，请稍后再试...
  
问题：重试一次大概率就能成功，但浪费了一次 Agent 循环 ❌
```

## 🎯 核心要点

- ✅ **三种错误类型**：已知、临时、未知，各有特点
- ✅ **三种处理策略**：try-except、tenacity、handle_tool_errors
- ✅ **策略选择**：根据错误类型选择合适的处理方式
- ✅ **生产环境**：通常需要组合使用三种策略
- ✅ **目标**：提升用户体验，避免 Agent 崩溃
