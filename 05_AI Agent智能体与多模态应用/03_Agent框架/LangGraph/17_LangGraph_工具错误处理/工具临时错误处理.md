---

## 📖 介绍

**临时错误**是指暂时性问题，如网络波动、API 限流等。这类错误重试大概率能成功。使用 `tenacity` 在工具函数上做自动重试，比让 Agent 反复调用更高效。

---

## 💡 适用场景

| 错误类型           | 示例                | 特点             |
| ------------------ | ------------------- | ---------------- |
| **网络超时** | `TimeoutError`    | 重试可能成功     |
| **连接失败** | `ConnectionError` | 服务器暂时不可用 |
| **API 限流** | HTTP 429            | 等待后重试可恢复 |
| **服务繁忙** | HTTP 503            | 稍后重试可能成功 |

## 💻 代码示例：搜索工具自动重试

```python
import os
import random
from dotenv import load_dotenv
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langgraph.prebuilt import create_agent
from tenacity import (
    retry,
    stop_after_attempt,
    wait_exponential,
    retry_if_exception_type,
)
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

load_dotenv()

llm = ChatOpenAI(
    base_url=os.getenv("OPENAI_API_BASE"),
    api_key=os.getenv("OPENAI_API_KEY")
)

# 模拟调用计数器，用来演示重试效果
call_count = {"search": 0}

@tool
@retry(
    stop=stop_after_attempt(3),           # 最多重试3次
    wait=wait_exponential(min=1, max=10), # 指数退避：1s, 2s, 4s...
    retry=retry_if_exception_type(        # 只重试临时性错误
        (TimeoutError, ConnectionError)
    ),
)
def search_web(query: str) -> str:
    """搜索互联网信息。"""
    call_count["search"] += 1
    print(f"  [第{call_count['search']}次调用] 搜索: {query}")

    # 模拟不稳定的外部API（前2次超时，第3次成功）
    if call_count["search"] <= 2:
        raise TimeoutError(f"API请求超时（第{call_count['search']}次）")

    return f"关于'{query}'的搜索结果：LangGraph是构建有状态AI应用的框架..."

# 创建 Agent
app = create_agent(llm, [search_web])

# 测试：tenacity 自动重试
call_count["search"] = 0  # 重置计数器
print("=== tenacity 自动重试演示 ===")
result = app.invoke({"messages": "搜索LangGraph教程"})
print(f"\nAI：{result['messages'][-1].content}")
```

### 📊 运行结果

```

  （超时，1秒后重试...）
```

## 🔧 tenacity 配置详解

### 1️⃣ 重试停止条件

```python
from tenacity import stop_after_attempt, stop_after_delay

# 最多重试3次
@retry(stop=stop_after_attempt(3))

# 或者：最多重试60秒
@retry(stop=stop_after_delay(60))

# 或者：两者结合（先满足者为准）
@retry(stop=(stop_after_attempt(3) | stop_after_delay(60)))
```

### 2️⃣ 重试间隔策略

```python
from tenacity import wait_fixed, wait_random, wait_exponential

# 固定间隔：每次等待2秒
@retry(wait=wait_fixed(2))

# 随机间隔：1-5秒之间
@retry(wait=wait_random(min=1, max=5))

# 指数退避：1s, 2s, 4s, 8s...（推荐）
@retry(wait=wait_exponential(min=1, max=60))
```

### 3️⃣ 重试触发条件

```python
from tenacity import retry_if_exception_type, retry_if_result

# 只重试特定异常
@retry(retry=retry_if_exception_type((TimeoutError, ConnectionError)))

# 根据返回值决定是否重试
@retry(retry=retry_if_result(lambda result: result is None))

# 组合条件
@retry(retry=(
    retry_if_exception_type(TimeoutError) |
    retry_if_result(lambda r: r == "error")
))
```

## 🎯 最佳实践

### ✅ 推荐配置

```python
@retry(
    stop=stop_after_attempt(3),              # 最多3次
    wait=wait_exponential(min=1, max=30),    # 指数退避 1-30秒
    retry=retry_if_exception_type((          # 只重试临时错误
        TimeoutError,
        ConnectionError,
        requests.exceptions.HTTPError
    )),
)
def call_external_api(query: str) -> str:
    """调用外部API。"""
    response = requests.get(f"https://api.example.com?q={query}", timeout=5)
    response.raise_for_status()
    return response.json()["data"]
```

### ⚠️ 注意事项

```python
# ❌ 错误：重试所有异常（包括参数错误）
@retry(stop=stop_after_attempt(3))
def bad_example(x: int):
    return 1 / x  # 如果x=0，重试3次也没用！

# ✅ 正确：只重试临时性错误
@retry(
    stop=stop_after_attempt(3),
    retry=retry_if_exception_type((TimeoutError, ConnectionError))
)
def good_example(url: str):
    response = requests.get(url, timeout=5)
    return response.text
```

## 📋 总结

| 特性                 | 说明                             |
| -------------------- | -------------------------------- |
| **适用错误**   | 临时错误（网络、限流、服务繁忙） |
| **处理方式**   | `tenacity` 自动重试，指数退避  |
| **Agent 感知** | ❌ 无感知，只拿到最终结果        |
| **优势**       | 高效、透明、节省 Agent 循环      |
| **关键配置**   | 重试次数、间隔策略、异常类型     |

---

## 🎯 核心要点

- ✅ **临时错误可恢复**：重试大概率成功
- ✅ **tenacity 自动重试**：在工具层面处理，Agent 无感知
- ✅ **指数退避**：避免频繁请求导致雪崩
- ✅ **精准重试**：只重试临时性错误，不重试参数错误
- ✅ **合理配置**：根据业务需求调整重试次数和间隔
