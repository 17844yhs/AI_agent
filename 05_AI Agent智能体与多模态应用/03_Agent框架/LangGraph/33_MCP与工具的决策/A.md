# 🎯 MCP 与工具的决策指南

## 📌 核心概念

### 自建 MCP Server vs 云端 MCP 服务

| 类型 | 特点 | 适用场景 |
|------|------|---------|
| **自建 MCP** | • 自己写代码（FastMCP）<br>• 自己部署（本地/云服务器）<br>• 自己维护 | 自定义业务逻辑 |
| **云端 MCP** | • 服务商已写好、部署、维护<br>• 只需连接 URL<br>• 按调用量付费或免费 | 通用能力（天气、地图、搜索、翻译等） |

---

## ⚖️ 何时用 MCP，何时用 @tool？

### 使用 @tool 的场景 ✅

- 🔢 简单的本地计算、格式转换
- 📦 只在当前项目中使用
- 💻 工具逻辑简单，几行代码搞定
- 🔒 不需要与其他应用共享

```python
@tool
def add(a: int, b: int) -> int:
    """两数相加"""
    return a + b
```

### 使用 MCP Server 的场景 ✅

- 🔗 需要连接外部服务（GitHub、数据库、API）
- 🔄 工具需要在多个 Agent/应用间共享
- 🏪 社区已有现成的 MCP Server 可用
- 🚀 工具有独立的部署和扩展需求
- 🌐 需要不同语言实现（Python/Node.js/Go 等）

---

## 💡 MCP 的核心理念

```
"一次编写，到处使用"

当你发现多个项目都需要同一个工具时：
└─ 把它封装为 MCP Server
   └─ 所有项目都能直接连接使用 ✅
```

## 🌳 工具选择决策树

```
需要工具？
│
├─ 简单本地操作？
│   └─ ✅ 用 @tool
│
├─ 需要连接外部服务？
│   └─ ✅ 用 MCP Server
│
├─ 只在当前项目用？
│   └─ ✅ 用 @tool
│
└─ 需要跨项目共享？
    │
    ├─ 社区有现成的 MCP Server？
    │   └─ ✅ 直接用
    │
    └─ 没有？
        └─ ✅ 自己封装 MCP Server
```

---

## 🎯 决策要点总结

### 快速判断法则

| 条件 | 推荐方案 |
|------|---------|
| 简单计算/转换 | `@tool` |
| 单项目使用 | `@tool` |
| 跨项目复用 | `MCP Server` |
| 连接外部 API | `MCP Server` |
| 社区有现成方案 | 直接用云端 MCP |
| 自定义业务逻辑 | 自建 MCP |

### 最佳实践

1. **优先使用 @tool**：简单场景保持轻量
2. **适时升级为 MCP**：当发现需要复用时再封装
3. **善用云端 MCP**：避免重复造轮子
4. **混合架构**：核心业务自建 + 通用能力云端

---

## 💡 核心要点

- 🎯 **@tool** 适合简单、本地、单项目场景
- 🔗 **MCP** 适合复杂、跨项目、外部服务集成
- ☁️ **云端 MCP** 提供即插即用的服务能力
- 🔄 **渐进式演进**：从 @tool 到 MCP，按需升级
- 🏪 **生态优先**：先找现成方案，再考虑自建
- 🌳 **决策树**：根据使用范围和需求复杂度选择
