# 🔌 MCP（Model Context Protocol）介绍

## 🎯 为什么需要 MCP？

### ❌ 问题场景

#### 场景1：自定义工具（传统方式）

```python
@tool
def search(query: str) -> str:
    """搜索信息"""
    return "搜索结果..."
```

**存在的问题：**
- 🔧 每个工具都要自己写、自己维护
- 🚫 工具无法被其他 Agent/应用复用

#### 场景2：不同 Agent 框架的工具不互通

```
LangGraph Agent 的工具 → 只能在 LangGraph 中用 ❌
Claude Agent 的工具   → 只能在 Claude 中用 ❌
OpenAI Agent 的工具   → 只能在 OpenAI 中用 ❌
```

#### 场景3：有了 MCP 之后 ✨

```
写一个 MCP Server（搜索工具）
├─ LangGraph Agent 可以用 ✅
├─ Claude Agent 可以用 ✅
├─ OpenAI Agent 可以用 ✅
└─ 任何支持 MCP 的客户端都能用 ✅
```

---

## 📌 核心概念

### 核心问题

**工具与框架耦合，无法跨 Agent 复用。**

### MCP 是什么？

**MCP（Model Context Protocol）** 是一个开放协议，让工具与服务可以**跨框架、跨模型复用**。

---

## 💡 MCP 的作用

### 🖼️ 形象比喻：USB 接口

```
❌ 没有 MCP = 每个设备有自己专属的接口
   ├─ 键盘用 A 接口
   ├─ 鼠标用 B 接口
   └─ U盘用 C 接口
   （互不兼容，无法通用）

✅ 有 MCP = 所有设备都用 USB 接口，插上就能用
   ├─ 键盘 → USB 接口 ✅
   ├─ 鼠标 → USB 接口 ✅
   └─ U盘 → USB 接口 ✅
   （统一标准，即插即用）
```

### MCP 架构组件

| 组件 | 类比 | 说明 |
|------|------|------|
| **MCP Server** | USB 设备 | 提供工具和服务（键盘、鼠标、U盘） |
| **MCP Client** | USB 接口 | 连接和使用工具（电脑上的 USB 端口） |
| **MCP Protocol** | USB 标准 | 统一的通信协议和规范 |

## 🎯 MCP 的核心价值

### 1️⃣ 工具复用

```
一次开发，多处使用
└─ 编写一个 MCP Server
   └─ 所有支持 MCP 的框架都能调用
```

### 2️⃣ 解耦框架

```
工具 ↔ 框架解耦
├─ 工具开发者：专注实现功能
└─ Agent 开发者：专注业务逻辑
```

### 3️⃣ 生态共享

```
丰富的 MCP Server 生态
├─ 文件系统访问
├─ 数据库查询
├─ Web 搜索
├─ API 调用
└─ ...（持续扩展）
```

---

## 💡 核心要点

- 🔌 **MCP** 是统一的工具调用协议
- 🔄 **跨框架复用**：一次开发，多框架使用
- 🧩 **解耦设计**：工具与框架分离
- 🌐 **开放生态**：丰富的 MCP Server 资源
- 🔗 **标准化接口**：类似 USB 即插即用
