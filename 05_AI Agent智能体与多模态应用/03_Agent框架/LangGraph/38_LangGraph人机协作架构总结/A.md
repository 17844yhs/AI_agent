# LangGraph 人机协作架构总结

## 一、三种 HITL 模式对比

| 模式 | 应用场景 | 实现方式 | 人类操作 |
|------|---------|---------|---------|
| **审批模式** | 高风险工具执行前 | 工具内调用 `interrupt()` | 批准 / 拒绝 |
| **反馈模式** | Agent 生成内容后 | 节点中调用 `interrupt()` + 条件循环 | 修改意见 / 批准 |
| **智能审批** | 按条件判断是否需要 | 工具内根据风险等级条件 `interrupt()` | 仅高风险时介入 |

---

## 二、关键注意事项

### ⚠️ 必知要点

**使用 `interrupt` 时必须配合 `checkpointer`**

- **原因**：没有 checkpointer，Graph 暂停后状态会丢失，无法恢复
- **后果**：人类审批后无法继续执行
- **常见错误**：初学者常忘记配置 checkpointer

```python
# 正确配置示例
from langgraph.checkpoint.memory import MemorySaver

app = builder.compile(checkpointer=MemorySaver())
```

## 三、架构总览

```
┌─────────────────────────────────────────────────────────┐
│                    Agent 执行流程                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  START → call_model → 工具调用判断 → tools → call_model  │
│                                 │                       │
│                                 ↓                       │
│                          [interrupt]                    │
│                                 │                       │
│                                 ↓                       │
│                          人类审批/反馈                   │
│                                 │                       │
│                                 ↓                       │
│                              END                        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**架构要点**：
- `call_model` 节点：调用 LLM 进行决策
- `tools` 节点：执行工具调用
- `interrupt`：根据条件暂停等待人类介入
- `checkpointer`：保存状态，支持断点续传

## 四、何时使用 HITL 的决策树

```
        是否涉及高风险操作？
               │
         ┌─────┴─────┐
         ↓           ↓
        是           否
         │           │
    需要人工审批    自动执行
         │
    ┌────┴────┐
    ↓         ↓
 批准执行   拒绝操作
```

**决策逻辑**：
1. 判断操作风险等级
2. 高风险 → 触发 HITL 审批
3. 中低风险 → 自动执行

## 五、最佳实践

### 1. 最小化人工介入

- 只在真正需要的地方加 `interrupt`
- 不要过度使用，否则用户会被频繁打断
- 失去自动化的意义

### 2. 提供清晰的上下文

- `interrupt` 的消息要说清楚：
  - **要做什么**：明确操作内容
  - **影响是什么**：潜在风险和后果
- 让人类能快速做出决策

### 3. 风险分级

- **低风险**：自动执行，无需干预
- **高风险**：暂停等待人工确认
- 判断维度：金额、类型、影响范围等

### 4. 给人类选择权

- 不要只有"批准/拒绝"二元选项
- 提供"修改"选项
- 让人类可以纠正 Agent 的错误

### 5. 记录审批日志

- **记录内容**：谁在什么时间审批了什么操作
- **目的**：方便事后追溯和审计
- **合规要求**：满足监管合规需求

---

## 六、核心要点总结

| 要点 | 说明 |
|------|------|
| **checkpointer 必要性** | 使用 interrupt 必须配合 checkpointer |
| **模式选择** | 根据场景选择审批模式、反馈模式或智能审批 |
| **用户体验** | 最小化中断，提供清晰上下文 |
| **风险控制** | 通过分级策略平衡效率与安全 |
| **可追溯性** | 记录审批日志支持审计 |
